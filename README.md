# RootMe

Локальное приложение для ведения генеалогического дерева. На этапе 0 доступны список персон, добавление, редактирование и удаление. Backend на Kotlin и Spring Boot работает с PostgreSQL через JPA, а Flyway применяет миграции при запуске. Интерфейс на React и TypeScript обращается к REST через прокси Vite.

## Запуск на Windows

Требуются JDK 17, Node.js 22 или 24 и запущенный Docker Desktop с Docker Compose.

В PowerShell из корня репозитория запустите PostgreSQL и backend.

```powershell
docker compose up -d --wait postgres
.\gradlew.bat bootRun
```

Во втором окне PowerShell из корня репозитория запустите интерфейс.

```powershell
cd frontend
npm.cmd install
npm.cmd run dev
```

Откройте [интерфейс RootMe](http://127.0.0.1:5173). Spring Boot слушает `127.0.0.1:8080`, PostgreSQL доступен на `127.0.0.1:5432`. Приложение предназначено для локальной работы. Для публикации потребуется аутентификация, авторизация и защита персональных данных.

По умолчанию используется база `rootme` и локальная учётная запись `rootme`. Если порт 5432 занят, задайте внешний порт для Docker Compose и соответствующий JDBC URL для Spring Boot в том же PowerShell, где будете запускать оба сервиса.

```powershell
$env:DB_PORT = "15432"
$env:DB_URL = "jdbc:postgresql://127.0.0.1:${env:DB_PORT}/rootme"
```

Чтобы задать другой пароль для новой базы, установите `DB_PASSWORD` перед первым запуском PostgreSQL и используйте то же значение при запуске backend. Для уже инициализированной базы смена переменной сама по себе пароль не меняет.

Остановите Vite и Spring Boot через Ctrl+C, затем выполните `docker compose down`. Данные хранятся в именованном Docker-томе `postgres16_data`. Команда `docker compose down -v` удаляет том вместе с данными.

## Сборка

```powershell
.\gradlew.bat build
cd frontend
npm.cmd install
npm.cmd run build
```

Gradle запускает существующие интеграционные тесты через Testcontainers, поэтому для сборки нужен Docker. Собранный UI можно проверять командой `npm.cmd run preview` на порту 4173 при запущенном backend.

## REST API

Существующие маршруты сохранились под префиксом `/api/v1/person`.

| Метод | Маршрут | Действие |
| --- | --- | --- |
| GET | `/get` | Список персон |
| GET | `/get/{uuid}` | Персона |
| POST | `/create` | Создать персону |
| PUT | `/edit/{uuid}` | Заменить редактируемые поля |
| DELETE | `/delete/{uuid}` | Удалить выбранную персону |

Даты передаются строками `YYYY-MM-DD` или `null`. Получение одной персоны и получение списка возвращают одинаковое представление персоны. Удаление корневой персоны удаляет только эту персону. Интерфейс помечает первую доступную карточку, если первоначальная корневая персона удалена. Поля прежней модели родства сохраняются в контракте и схеме совместимости. Явное редактирование связей и выбор корня дерева относятся к этапу 1. Данных для переноса из прежней базы нет.

## Дальнейшие этапы

- Этап 1. Интерактивное дерево на React Flow. Отображение по поколениям с начальной глубиной до пяти поколений в обе стороны, смена корня, сворачивание веток, добавление родственника из карточки, биологическое и приёмное родительство, партнёрства, бывшие супруги и дети от разных партнёров.
- Этап 2. Фотографии, биографии, альтернативные имена, поиск и навигация. Пустые поля уже скрыты в карточках, типы связей и цвет карточек по полу будут видны в дереве.
- Этап 3. Файловые резервные копии независимо от PostgreSQL, проверка целостности, восстановление, импорт Excel/Access и экспорт GEDCOM.
- Отложены установщик Windows, автоподстановка места рождения и расширение покрытия бизнес-логики тестами.
