# RootMe

Локальное приложение для ведения генеалогического дерева. В интерфейсе можно выбирать корень, просматривать предков и потомков, добавлять персон, родительские связи и партнёрства. Backend на Kotlin и Spring Boot работает с PostgreSQL через JPA, а Flyway применяет миграции при запуске. Интерфейс на React и TypeScript отображает дерево через React Flow и обращается к REST через прокси Vite.

## Запуск на Windows

Требуются Windows 10 или 11, JDK 17, Node.js 24 или 22.12+ и Docker Desktop с Docker Compose. Права администратора для скриптов не нужны.

**Запуск одним кликом.** Дважды щёлкните `start.bat`. Он запустит Docker Desktop при необходимости, дождётся PostgreSQL, подготовит backend, запустит Vite и откроет [RootMe](http://127.0.0.1:5173). Если приложение уже запущено этим скриптом, откроется существующий экземпляр.

При первом запуске Gradle собирает backend. При следующих запусках скрипт использует проверенный JAR, пока исходники и настройки сборки остаются прежними. Чтобы принудительно запустить Gradle, остановите приложение и выполните `.\start.bat -Rebuild` из корня проекта.

**Остановка одним кликом.** Дважды щёлкните `stop.bat`. Скрипт остановит Vite, дождётся штатного завершения Spring Boot и затем выполнит `docker compose down` для проекта RootMe. Docker Desktop продолжит работу. Именованный том PostgreSQL, фотографии и резервные копии сохранятся.

Журналы находятся в `logs/`. Для диагностики начните с `backend.error.log`, `backend.log`, `frontend.error.log`, `gradle.error.log` или `npm-ci.error.log`. В `.rootme-run/` хранятся данные о запущенных процессах. Оставьте этот каталог на месте, пока приложение работает.

- **Не найден JDK или npm.** Укажите путь к JDK 17 в `JAVA_HOME` или установите совместимый Node.js и добавьте его в `PATH`. Скрипт также ищет Node.js во встроенном рантайме IntelliJ IDEA.
- **Порт занят.** Остановите предыдущий ручной запуск либо задайте свободные порты. `SERVER_PORT` меняет порт Spring Boot и адрес прокси Vite, `ROOTME_FRONTEND_PORT` — порт Vite, а `DB_PORT` — внешний порт PostgreSQL. Для запуска двойным щелчком задайте нужные переменные в настройках среды Windows. Из PowerShell можно передать их через `$env:...` и вызвать `.\start.bat`.
- **PostgreSQL не готов.** Проверьте Docker Desktop и журналы `postgres-start.log` и `postgres-start.error.log`. Для уже созданной базы используйте пароль, с которым она была инициализирована.
- **Backend не завершился вовремя.** PostgreSQL останется запущенным. Проверьте `backend.log` и повторите `stop.bat` после завершения backend.

### Ручной запуск и остановка

В PowerShell из корня репозитория запустите PostgreSQL и backend.

```powershell
docker compose up -d --wait postgres
.\gradlew.bat bootRun
```

Во втором окне PowerShell из корня репозитория запустите интерфейс.

```powershell
cd frontend
npm.cmd ci
npm.cmd run dev
```

Откройте [интерфейс RootMe](http://127.0.0.1:5173). Spring Boot слушает `127.0.0.1:8080`, PostgreSQL доступен на `127.0.0.1:5432`. Приложение предназначено для локальной работы. Для публикации потребуется аутентификация, авторизация и защита персональных данных.

По умолчанию используется база `rootme` и локальная учётная запись `rootme`. Если порт 5432 занят, задайте внешний порт для Docker Compose и соответствующий JDBC URL для Spring Boot в том же PowerShell, где будете запускать оба сервиса.

```powershell
$env:DB_PORT = "15432"
$env:DB_URL = "jdbc:postgresql://127.0.0.1:${env:DB_PORT}/rootme"
```

Чтобы задать другой пароль для новой базы, установите `DB_PASSWORD` перед первым запуском PostgreSQL и используйте то же значение при запуске backend. Для уже инициализированной базы смена переменной сама по себе пароль не меняет.

Остановите Vite и Spring Boot через Ctrl+C, затем выполните `docker compose down`. Данные хранятся в именованном Docker-томе `postgres16_data`. Команда `docker compose down -v` удаляет том вместе с данными.

## Тесты

`.\gradlew.bat build` собирает backend и запускает интеграционные тесты. Для них нужен запущенный Docker. Testcontainers поднимает отдельную PostgreSQL, а тесты фотографий используют временный каталог.

Для тестов frontend запустите `npm.cmd test` из `frontend` после `npm.cmd ci`. Требуется Node.js 22.12 или новее в ветке 22 либо Node.js 24.

## REST API этапа 1

| Метод | Маршрут | Действие |
| --- | --- | --- |
| GET | `/api/v1/persons?query=…` | Список и поиск по имени, фамилии или отчеству без учёта регистра |
| GET | `/api/v1/persons/{id}` | Полная карточка, прямые связи и краткие сведения о родственниках |
| POST | `/api/v1/persons` | Создать персону |
| PATCH, DELETE | `/api/v1/persons/{id}` | Изменить персону или удалить её вместе с записями её связей |
| POST | `/api/v1/persons/{id}/relatives` | Создать или привязать родителя, ребёнка или партнёра |
| POST | `/api/v1/relationships/parent-child` | Добавить биологическую, приёмную или неродную родительскую связь |
| DELETE | `/api/v1/relationships/parent-child/{id}` | Удалить родительскую связь |
| POST | `/api/v1/partnerships` | Добавить союз |
| PATCH, DELETE | `/api/v1/partnerships/{id}` | Изменить или удалить союз |
| GET | `/api/v1/tree?rootPersonId={id}&ancestors=5&descendants=5` | Получить подграф и признаки скрытых веток |

Даты передаются как `YYYY`, `YYYY-MM`, `YYYY-MM-DD` или `null`. В PATCH отсутствующее поле сохраняет значение, а явный `null` очищает необязательное поле. Ошибки возвращаются в формате Problem Details с полем `code` и, когда применимо, объектом `errors`.

Для `/relatives` передайте `role` (`PARENT`, `CHILD` или `PARTNER`) и одно из полей `person` или `existingPersonId`. Для родителя и ребёнка укажите `parentChildType`, для партнёра — объект `partnership` с типом, статусом и необязательными датами. Ответ `409 PARTNERSHIP_REPEAT_CONFIRMATION_REQUIRED` позволяет подтвердить отдельный исторический союз с неполными или неизвестными датами через `allowRepeat: true`. Код `DUPLICATE_PARTNERSHIP` означает конфликт, который нельзя подтвердить.

Дерево независимо обходит биологические и приёмные связи вверх и вниз. Глубина считается по кратчайшему пути в каждом направлении. По умолчанию глубина равна пяти поколениям, а `0` отключает основной обход в этом направлении. Настройка `rootme.tree.max-depth` задаёт допустимый максимум (по умолчанию 10), который сервер возвращает в `maxDepth`.

При включённых обоих направлениях добавляются другие дети общих родителей из основного обхода, если на уровне родителя допустим переход вниз. Также добавляются другие известные биологические и приёмные родители потомков из основного обхода. Прямые `STEP`-связи добавляются от узлов основного обхода, когда в соответствующем направлении есть запас глубины. Рекурсивного обхода по `STEP` нет. После этого один раз добавляются прямые партнёры отобранных персон, включая бывших. Семьи контекстных персон автоматически не разворачиваются. В ответе каждая персона встречается один раз и возвращаются связи между всеми попавшими в выдачу персонами.

`hiddenBranches` отмечает прямых соседей за пределами выдачи. Поля `nextAncestorDepth` и `nextDescendantDepth` указывают следующий шаг, который включает прямого родственника граничного узла. Для контекстной персоны с невидимыми родственниками можно сменить корень. Свёрнутые ветки остаются состоянием интерфейса. Для слишком широкого подграфа API возвращает `400` и предлагает выбрать другой корень или уменьшить глубину.

Flyway V2 сохраняет персон и их UUID, а существующим полным датам назначает точность дня. Однозначные пары из `spouse_id` переносятся со статусом `UNKNOWN`. Если в V1 есть нетипизированные записи `person_parentage` или неоднозначные относительные метки, Flyway останавливает миграцию до удаления старой схемы.

## Профили и фото API этапа 2

`GET /api/v1/persons` принимает `query`, `birthYear`, `page` (с нуля) и `size` (1–100, по умолчанию 30). Ответ содержит `items`, `page`, `size` и `total`. Запрос ищет слова в любом порядке по имени, фамилии, отчеству, фамилии при рождении и альтернативным именам.

Справочник персон позволяет открыть карточку или сделать найденную персону корнем, в том числе если у неё нет связей. В карточке доступны разделы «Основное», «Связи», «Биография» и «Фотографии». Миниатюра основного фото показывается в дереве, карточке и результатах поиска.

Подробности персоны содержат поля профиля, альтернативные имена и основное фото. Для имён доступны `POST /api/v1/persons/{id}/alternative-names`, а также `PATCH` и `DELETE` по UUID имени внутри этого ресурса.

| Метод | Маршрут | Действие |
| --- | --- | --- |
| GET, POST | `/api/v1/persons/{id}/photos` | Метаданные фотографий или загрузка multipart с полями `file`, `caption`, `takenDate` |
| GET, PATCH, DELETE | `/api/v1/photos/{id}` | Оригинал, изменение подписи и даты или удаление |
| GET | `/api/v1/photos/{id}/thumbnail` | Миниатюра |
| PUT | `/api/v1/persons/{id}/primary-photo` | Выбор основной фотографии с телом `{ "photoId": "…" }` |

Принимаются JPEG и PNG до 20 МиБ и 40 мегапикселей. Миниатюры имеют длинную сторону до 320 px. Максимум подписи — 1000 символов, биографии — 100 000, новых значений заметок — 10 000. Flyway V3 сохраняет старые заметки любой длины.

Оригиналы и миниатюры сохраняются в `data/photos` относительно рабочего каталога backend. Для другой папки задайте `ROOTME_STORAGE_PHOTOS_DIRECTORY` или `rootme.storage.photos-directory`. Используйте каталог, выделенный одной базе RootMe, на файловой системе с поддержкой атомарного переименования. Каталог PostgreSQL и каталог фотографий сохраняются отдельно. Удалённые фотографии очищаются в фоне после коммита. При отсутствии файла метаданные сохраняются, а API возвращает `PHOTO_FILE_MISSING`.

Изменяющие запросы браузера принимаются только от локальных origin интерфейса и backend. Публикация в интернете требует отдельного анализа безопасности и аутентификации.

## Резервные копии

Откройте «Резервные копии» в верхней панели. «Создать копию» сохраняет ZIP на сервере и предлагает скачать его. «Проверить целостность» принимает ZIP с диска, сверяет контрольные суммы и ссылки между записями и показывает количество записей каждого типа. Проверка не изменяет базу или хранилище фотографий.

Для восстановления подключите отдельную пустую базу RootMe с помощью `DB_URL` и выделите ей отдельный каталог фотографий. Выберите ZIP, проверьте его, затем нажмите «Восстановить в пустую базу» и подтвердите действие. Существующие персоны блокируют восстановление. Сервер повторно сверяет архив с результатом проверки перед записью, сохраняет UUID и связи, а миниатюры пересоздаёт из оригиналов. При конфликте с папкой фотографии восстановление останавливается, сохраняя существующие файлы.

Копии хранятся в `backups/`, либо в каталоге `ROOTME_STORAGE_BACKUPS_DIRECTORY`. ZIP формата RootMe v1 содержит `manifest.json`, `data.json` и оригиналы в `photos/{photoId}/`. Данные и оригиналы записываются из согласованного снимка. Если оригинал отсутствует или его SHA‑256 отличается от записанного при загрузке, создание копии останавливается. Миниатюры, временные файлы и очередь очистки в копию не входят.

Максимум для ZIP и суммарного объёма распакованных данных и оригиналов — 2 ГиБ, для JSON-данных — 64 МиБ. Архивы содержат персональные данные и фотографии в открытом виде. Храните их вместе с другими приватными файлами.

API предоставляет `POST /api/v1/backups` для создания, `GET /api/v1/backups/{id}` для скачивания и `POST /api/v1/backups/verify` для проверки ZIP, передаваемого как тело запроса с типом `application/zip`.

`POST /api/v1/backups/restore` принимает тот же ZIP как тело запроса. Передайте заголовки `X-RootMe-Confirm-Restore: true` и `X-RootMe-Backup-SHA256` со значением `archiveSha256` из ответа проверки.

## Импорт и экспорт

Раздел «Импорт и экспорт» принимает Excel (`.xls`, `.xlsx`) и Access (`.mdb`, `.accdb`). Выберите лист или локальную таблицу, сопоставьте колонки с полями профиля и проверьте предпросмотр перед подтверждением. В Excel первый ряд с данными используется как заголовок. Обязательное поле — имя. Текстовые даты принимаются как `YYYY`, `YYYY-MM` и `YYYY-MM-DD`, а ячейки Excel и столбцы Access с типом даты читаются как календарные даты. Формулы Excel не вычисляются. Парольные файлы и связанные таблицы Access не импортируются.

Импорт добавляет только персон. Для таблиц без согласованной схемы связи, фото и идентификаторы источника не переносятся. Совпадение имени, фамилии, отчества и даты рождения с той же точностью считается возможным дубликатом. Такие строки показываются и пропускаются после подтверждения. Если есть ошибки, исправьте файл и повторите предпросмотр. Файл ограничен 20 МиБ и 5 000 заполненных строк на выбранном листе или в таблице.

GEDCOM 7 выгружается как UTF‑8 файл `rootme.ged`. Экспорт сохраняет персон, частичные даты, семейные записи, биологическое и приёмное родство. Неродное родство передаётся с пояснением `PEDI OTHER`, а статус и окончание союза — в заметках. При нескольких союзах одной пары экспорт не назначает ребёнка конкретному союзу. Предупреждения отображаются после выгрузки. Для переноса оригиналов фото и полного восстановления данных используйте ZIP-копию RootMe.

API импорта принимает multipart-запросы с `file` на `POST /api/v1/imports/persons/sources`, `/preview` и `/apply`. Для предпросмотра добавьте JSON-часть `options` с `source` и `mapping` (номера колонок с нуля), для применения — также `fingerprint` из результата предпросмотра. `GET /api/v1/exports/gedcom` скачивает файл и возвращает коды предупреждений в `X-RootMe-Gedcom-Warnings`.

### Импорт генеалогического дерева из MDB

В диалоге «Импорт и экспорт» выберите MDB в разделе «Импорт генеалогического дерева из Access». Нажмите «Проверить файл и показать предпросмотр», проверьте количества и предупреждения и подтвердите импорт. После завершения RootMe откроет импортированное дерево.

Сервер распознаёт схему по локальным таблицам `PERS`, `FAM`, `CHILD`, `DATES`, `PLACE`, `CHILD_TYPE` и `FAM_TYPE`, их ключам и типам столбцов. Связи строятся по идентификаторам источника и типам из справочников. Семейная запись с одним участником сохраняет известное родительство, если на неё ссылается запись о ребёнке. Отсутствие отметки о разводе сохраняется как неизвестный статус союза.

- `POST /api/v1/imports/genealogy-mdb/preview` принимает multipart-часть `file` и возвращает количества, предупреждения и `fingerprint`.
- `POST /api/v1/imports/genealogy-mdb/apply` принимает тот же файл и JSON-часть `options` с `fingerprint`. Если в предпросмотре есть записи без имени, параметр `allowUnnamedPersons: true` подтверждает использование подписи «Имя неизвестно» для таких записей.

Применение требует пустой БД RootMe. Персоны и связи записываются одной транзакцией. Поддерживаемые частичные даты переносятся с исходной точностью, неподдерживаемые даты персоны и названия мест сохраняются в её заметках. Фотографии, ссылки на документы, записи из таблицы альтернативных имён, дополнительные события, заметки о союзах и настройки дерева пока выходят за рамки импорта.
